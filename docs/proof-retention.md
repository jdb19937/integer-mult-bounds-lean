## Remaining candidates

`conservative_candidate_files` means outside the protected import closures,
not approved for deletion. The October 15 review retained these files wherever
future usefulness was uncertain. In particular, native stream and phase kernels,
repair and address-layout machinery, network/conjugation mathematics, resampling,
source-length alternatives and packed-product cost bridges can support the
stronger-bound roadmap. Milestone bundles retain their links to the archived
plans. Legacy audits and generator pilots remain useful verification resources.

The review removed only `Machine/UnitPhaseMultiplicity.lean` (57 lines).
`Machine/UnitPhasePolynomialMultiplicity.lean` retains the same eight selected
ports, fixed machine, output word and exact cost. Its input hypotheses use the
equivalent encoded-binary representation and reverse the order of conjunctions;
`CountedLoopReuseAlphabet.encoding_binary` supplies the representation equality.
No Lean module besides the aggregate root imported the removed file. Its
component entry and aggregate import were removed; archived plan tables remain
historical snapshots. See the [recovery manifest](retired-duplicate-multiplicity.json).
No retained theorem body, bound, proof limit or axiom policy was changed.

The earlier audit omitted active compact-control checks and reported their
supporting modules as candidates. `retain_for_development` now explicitly
protects that work, including compact host modules still under construction.
This is a conservative source/import review, not a declaration-level proof that
every retained file will be needed.

**A subset of the candidate list need not be removable alone.** Surviving
legacy modules may import it even though the final theorem does not. Every
removal batch must include its unused transitive importers, or otherwise
resolve those imports, and must exclude protected modules. This is why the
426 controller candidates were retired with 209 dependent wrappers.

The import closure is conservative: declarations inside retained modules may
be unused, but that requires a separate declaration-level or import-minimization
audit. Candidates can also retain value for the stronger `83/10^12` target;
Git preserves the retired development.

## Proof-integrity checks

`CompletedProofCheck.lean` imports the final theorem directly, independently
of the all-components root, and audits every imported project declaration for
only `propext`, `Classical.choice` and `Quot.sound`. It is included in CI.
The main `AxiomAudit.lean` continues to audit every declaration imported by the
surviving library root; all other focused audit files are retained.

Reproduce the current inventory and checks with:

```sh
python3 -m unittest discover -s scripts -p test_proof_retention.py
python3 scripts/proof-retention.py --manifest docs/proof-retention.json --check
python3 scripts/check-lean-safe.py CompletedProofCheck.lean
```

Omit `--check` to refresh the manifest. The audit script never deletes Lean
files. A deletion must also prune `IntegerMultBounds.lean`, update retired
component documentation, regenerate plan status and pass the guarded build
and all retained audits.
